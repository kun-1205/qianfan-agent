# 迭代记录

## 2025-03　项目启动

- **目标**：搭建可根据个人情况定制训练计划与每日饮食的健身顾问智能体
- **动作**：整理营养学与训练资料，构建知识库；上传文档验证切片效果
- **问题**：初期切片粒度过大，召回内容夹杂大量无关信息，方案引用不准确
- **解决**：调整切片粒度，按小节切分并保留标题层级

## 2025-04　Prompt 工程迭代

| 版本 | 改动内容 | 观察到的效果 |
|---|---|---|
| v1 | 通用健身助手指令 | 回答质量不稳定，方案不成体系 |
| v2 | 加入角色设定 + 输出格式约束 | 计划结构清晰度明显提升 |
| v3 | 加入安全兜底规则（转介 / 劝阻） | 安全类用例合规率大幅提升 |
| v4 | 加入任务拆解（多约束问题） | 复合问题约束满足率提升 |

**关键发现**：把「安全提示」做成输出格式里的**固定字段**（【注意事项】），
比在 Prompt 里写一句「请注意安全」有效得多 ——
前者是必须产出，后者靠模型自觉。

## 2025-05　测试与评估

- **建立测试用例集**：65 条，分 9 类（其中安全类 13 条）
- **评估方式**：人工逐条评分（完全正确 2 分 / 部分正确 1 分 / 错误 0 分）
- **发现的高频问题**：
  1. **安全类误判** —— 对「怀孕了想减脂」直接给出方案而未转介医生（最严重）
  2. **复合问题漏答** —— 只回应最显眼的条件，忽略其他约束（已用任务拆解缓解）
  3. **矛盾信息硬选** —— 遇到资料冲突时倾向选一个，而非指出冲突
  4. **极端数据未识别** —— 身高 250cm、体重 30kg 等异常输入照常计算

## 复盘

**做得好的**
- 把安全兜底作为一等公民设计，而不是事后打补丁
- 建立了可复用的评估方法，而非凭感觉调 Prompt
- 用例覆盖九类场景，包括最容易被忽略的安全类

**如果重做会怎么改**
- 更早建立测试集（v1 就建），用数据驱动迭代而非事后验证
- 安全规则可以做成独立的前置校验层，而不只是 Prompt 约束
- 引入自动评估（LLM-as-judge）降低人工评分成本，但安全类仍需人工复核
